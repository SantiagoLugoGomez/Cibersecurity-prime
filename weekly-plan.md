# Weekly plan

A roadmap only works if it fits a real week. You are carrying a full engineering course load, so the default plan is deliberately light and sustainable. The intensive plan is for breaks, when you have whole days free. Consistency over months beats bursts that burn you out.

## Principles

- **Protect the degree first.** Your courses come before this roadmap. During exam weeks, drop to the maintenance plan below without guilt.
- **Small and regular wins.** Four focused hours spread across the week beat one exhausting Saturday.
- **One active track at a time.** Do not run Phase 2 machines and a new certification and a CTF in the same week. Finish, then move on.
- **Protect one rest day.** A day with no security work is part of the plan, not a failure.
- **Write as you go.** Every solve gets a writeup within 48 hours, or it did not really happen.

## Semester plan (sustainable): about 7.5 hours per week

This maps the four weekly sessions from the [roadmap format](roadmap/README.md#the-weekly-session-format) (R, P, D, E) onto real days, plus a short review slot and 10 minutes of flashcards most days. It overlaps on purpose with your courses (see [degree-connections.md](degree-connections.md)) so the two reinforce each other.

| Day | Session | Time | Focus |
|---|---|---|---|
| Monday | R | 75 min | Read and study the week's material; write flashcards |
| Tuesday | rest or flashcards only | 10 min | Spaced-repetition review |
| Wednesday | P | 90 min | Guided practice: labs, levels, drills |
| Thursday | E | 60 min | English on the week's topic ([english/](english/README.md)) |
| Friday | rest or flashcards only | 10 min | Spaced-repetition review |
| Saturday | D | 3 h | Deep practice: a machine, build, tool or investigation, ending in a writeup |
| Sunday | review | 30-45 min | Answer check-yourself questions, commit the deliverable, update [progress.md](progress.md), plan next week ([weekly-review template](templates/weekly-review.md)) |

Do 10 minutes of flashcards on as many days as you can; it is the highest-return habit. How to run each session well is in [study-system.md](study-system.md).

**Weekly checklist**

- [ ] R, P, D and E sessions done
- [ ] Daily-ish flashcard reviews
- [ ] Check-yourself questions answered from memory
- [ ] Deliverable committed
- [ ] [progress.md](progress.md) updated and next week planned

**During exam weeks (maintenance, about 2 hours):** keep only the R (read) session and daily flashcards. Pause P, D and E, and let the schedule slide by a week rather than skipping a deliverable. A very light week is easier to recover from than a full stop.

## Break plan (intensive): 25 to 35 hours per week

Use one break per year as a sprint: finish a phase, do a specialization deep dive, or prepare for a certification exam. This plan is five days on, two off.

| Day | Morning (3 hours) | Afternoon (3 hours) | Evening (1-2 hours) |
|---|---|---|---|
| Monday | New material for the phase or track | Guided labs on the day's topic | Notes and English listening |
| Tuesday | Theory and reading | Hands-on applying it | Writeup |
| Wednesday | Machine or project work | Continue; push through blockers | Notes |
| Thursday | New material | Labs | Speaking practice out loud |
| Friday | Project work | Finish and document | Writeup and publish |
| Saturday | Rest | Rest | Optional online CTF with a team |
| Sunday | Rest | Rest | Light review and plan the next week |

**Weekly goal during a break:** finish one phase block or one certification's worth of preparation, plus two published writeups or one portfolio project milestone.

## Mapping phases to the calendar

This is a guide, not a contract. Move slower if a semester is heavy; the order matters more than the dates.

| Period | Main focus |
|---|---|
| Semester 2 (now) | Phase 0, with Git and Linux first |
| Break after semester 2 | Finish Phase 0; start Phase 1 |
| Semester 3 | Phase 1 (alongside Fundamentals of Cybersecurity), begin Phase 2 |
| Break | Phase 2 intensive: CTFs, wargames, first machines |
| Semester 4 | Continue Phase 2; consolidate writeups |
| Semester 5 | Phase 3: run the six samplers |
| Break | Phase 3 deep dive in the chosen track |
| Semester 6 | Phase 3 project; begin Phase 4 (first certification) |
| Semester 7 onward | Phase 4: certifications, projects, bug bounty, community |

## Staying consistent

- Put the Saturday block in your calendar as a fixed appointment.
- Track streaks in [progress.md](progress.md); seeing a chain of done weeks is motivating.
- If you miss a week, do not try to make it up in one day. Return to the normal plan.
- Review the plan at the end of each semester and adjust the hours to what actually happened, not what you hoped.
