# Weekly plan

A roadmap only works if it fits a real week. You are carrying a full engineering course load, so the default plan is deliberately light and sustainable. The intensive plan is for breaks, when you have whole days free. Consistency over months beats bursts that burn you out.

## Principles

- **Protect the degree first.** Your courses come before this roadmap. During exam weeks, drop to the maintenance plan below without guilt.
- **Small and regular wins.** Four focused hours spread across the week beat one exhausting Saturday.
- **One active track at a time.** Do not run Phase 2 machines and a new certification and a CTF in the same week. Finish, then move on.
- **Protect one rest day.** A day with no security work is part of the plan, not a failure.
- **Write as you go.** Every solve gets a writeup within 48 hours, or it did not really happen.

## Semester plan (sustainable): 6 to 8 hours per week

This assumes a normal week during the semester. It overlaps on purpose with your courses (see [degree-connections.md](degree-connections.md)) so the two reinforce each other.

| Day | Time | Focus |
|---|---|---|
| Monday | 1 hour | Reading: a resource from the current phase, or a professional text ([english/reading-professional-material.md](english/reading-professional-material.md)) |
| Tuesday | rest or overflow | No security work by default |
| Wednesday | 1.5 hours | Hands-on: labs or challenges for the current phase |
| Thursday | 1 hour | English for the field ([english/](english/README.md)): glossary, listening or speaking |
| Friday | rest or overflow | No security work by default |
| Saturday | 2.5 to 3 hours | Main hands-on block: a machine, a set of labs, or a project |
| Sunday | 0.5 to 1 hour | Writeup of the week's work and plan the next week; update [progress.md](progress.md) |

**Weekly checklist**

- [ ] One reading block done and noted
- [ ] One substantial hands-on block done
- [ ] One English block done
- [ ] One writeup or project update committed to the repo
- [ ] [progress.md](progress.md) updated

**During exam weeks (maintenance, about 2 hours):** keep only the Monday reading hour and one 1-hour English block. Everything else pauses. Do not break the habit entirely; a very light week is easier to recover from than a full stop.

## Break plan (intensive): 25 to 35 hours per week

Use one break per year as a sprint: finish a phase, do a specialization deep dive, or prepare for a certification exam. This plan is five days on, two off.

| Day | Morning (3 hours) | Afternoon (3 hours) | Evening (1-2 hours) |
|---|---|---|---|
| Monday | New material for the phase or track | Guided labs on the day's topic | Notes and English listening |
| Tuesday | Theory and reading | Hands-on applying it | Writeup |
| Wednesday | Machine or project work | Continue; push through blockers | Notes |
| Thursday | New material | Labs | Speaking practice out loud |
| Friday | Project work | Finish and document | Writeup and publish |
| Saturday | Rest | Rest | Optional online CTF with a team |
| Sunday | Rest | Rest | Light review and plan the next week |

**Weekly goal during a break:** finish one phase block or one certification's worth of preparation, plus two published writeups or one portfolio project milestone.

This is a guide, not a contract. Move slower if a semester is heavy; the order matters more than the dates.

## Staying consistent

- Put the Saturday block in your calendar as a fixed appointment.
- Track streaks in [progress.md](progress.md); seeing a chain of done weeks is motivating.
- If you miss a week, do not try to make it up in one day. Return to the normal plan.
- Review the plan at the end of each semester and adjust the hours to what actually happened, not what you hoped.
