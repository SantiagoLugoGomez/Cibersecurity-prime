# Writeups

Documenting every box and challenge you solve is what turns practice into a portfolio. A good writeup proves you understand the attack, not just that you copied commands, and the habit of writing clearly in English is itself a career skill ([english/writing-reports.md](../english/writing-reports.md)).

## How to use this folder

1. Copy [`TEMPLATE.md`](TEMPLATE.md) to a new file named `YYYY-MM-DD-platform-target.md`.
2. Fill it in within 48 hours of solving, while the details are fresh.
3. Keep screenshots and large captures in a subfolder named after the writeup, or link to them.

[`2026-example-juice-shop-login-sqli.md`](2026-example-juice-shop-login-sqli.md) is a complete example written to the standard to aim for.

## What you may publish

- **Fine to share:** your own home-lab targets, OWASP Juice Shop and DVWA, picoCTF/picoGym challenges, OverTheWire (write about method, not stored passwords), retired Hack The Box machines, and anything a platform explicitly allows.
- **Do not publish:** writeups for **active** Hack The Box content. HTB's rules allow public writeups only for retired content; publishing active-machine writeups violates their terms. Check whether a machine has retired first.
- **Think before sharing:** some CTFs forbid writeups until the event ends. Read the rules.

Keep solutions to active, graded or exam content in a local folder that Git ignores (the repo's `.gitignore` excludes `private/`), never in this public folder.
